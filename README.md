# Outcome Skills

## One brief in. One finished result out.

**Free public test: get one useful sales asset you can use immediately.**

**No prompt engineering. No subscription.**

Not another prompt pack. Turn one usable brief, verified result, or real inbound
objection into one defined, review-ready sales asset during a free public test.

> **A result gateway that turns your supplied sales context into one named,
> review-ready deliverable—with sources, assumptions, and limits kept visible.**

- **Test the artifact, not a subscription.** The public test has no charge,
  wallet, or merchant account.
- **Your facts stay attached.** Supplied numbers, dates, names, units, and exact
  quotations remain traceable; unknowns stay marked.
- **Get one useful first version.** A valid input produces a defined artifact,
  not an intake questionnaire or a library of generic prompts.

## The three deliverables

There are exactly three public Skills. All three are free during the public test
period.

### Outcome Offer (`outcome-offer`)

**Turn a rough service into a sellable offer card.**

**Free during the public test period.**

- **Best input:** an idea, service, product, audience, or rough problem.
- **You receive:** one from-to outcome, product name, target buyer and buying
  moment, deliverables, three result-led benefits, risk reversal, three
  headlines, and a paste-ready sales block.
- **Result contract:** specific enough to brief a copywriter without another
  strategy call. Missing business facts remain labeled assumptions or
  unconfirmed fields.
- **It does not imply:** revenue, leads, conversion, or sales results.
- **Controlled example:** [Two-Day Notion Client System](examples/outcome-offer.md),
  generated by a no-money demo fixture.

### Proof Pack (`proof-pack`)

**Turn verified results into sales-ready proof.**

**Free during the public test period.**

- **Best input:** verified customer results, metrics, notes, or exact
  testimonial text.
- **You receive:** one proof headline; a two-sentence proposal blurb; a
  120–180-word case story (or locale-equivalent); exactly three evidence
  bullets; one social post; one sales-conversation version; claim
  traceability; missing evidence; and a quality check.
- **Result contract:** supplied numbers and exact quotations remain traceable.
  Calculations are labeled `Derived` with their source figures, and missing
  evidence remains visible.
- **It does not imply:** causality, operational impact, conversion, sales, or
  revenue impact.
- **Controlled example:** [WhatsApp reminder proof](examples/proof-pack.md),
  generated by a no-money demo fixture.

### Reply to Close (`reply-to-close`)

**Turn one live objection into a grounded next-step reply.**

**Free during the public test period.**

- **Best input:** one inbound prospect message or objection plus available
  offer context.
- **You receive:** one primary reply under 90 words (or locale-equivalent), one
  short alternative under 40 words, an objection classification, one shared
  low-friction next step, assumptions and traceability, and a quality check.
- **Result contract:** the reply advances exactly one low-friction next step
  while preserving supplied wording, figures, dates, and quotations.
- **It does not imply:** a discount, trial, refund, feature, guarantee, meeting,
  booking, purchase, or close. It is for real inbound context, not cold
  outreach.
- **Controlled example:** [Small-shop price objection reply](examples/reply-to-close.md),
  generated by a no-money demo fixture.

## Quick start

Requires Python 3.11 or newer.

```text
python -m pip install -e .
python scripts/install.py --target codex --scope project --dry-run
python scripts/install.py --target codex --scope project
```

The installer can copy all three complete Skill directories or one named Skill.
It refuses same-name destinations unless `--force` is explicit. Use `--dry-run`
first, especially before a forced replacement.

| Host | Project/workspace scope | User scope | Verification note |
| --- | --- | --- | --- |
| Codex | `.agents/skills` | `~/.agents/skills` | Open `/skills` or invoke `$outcome-offer`; `.agents/skills` is canonical. |
| JoyCode | `.joycode/skills` | `~/.joycode/skills` | Check the scope and path in Settings → Skills. JoyCode support for `agents/openai.yaml` is not claimed. |
| OpenClaw | `skills/` | `~/.openclaw/skills` | An active workspace checkout already discovers this repository's top-level `skills/`, so no copy is needed. |

Select another host or user scope explicitly:

```text
python scripts/install.py --target joycode --scope user --dry-run
python scripts/install.py --target openclaw --scope project --project-root /path/to/workspace --dry-run
# Install just one independent Skill:
python scripts/install.py --target codex --scope project --skill proof-pack
```

The `skills/` tree in this repository is the only installation source of truth.
Copy complete directories, never only `SKILL.md`; the clients, references, and
optional Codex metadata are part of each portable folder. Detailed deployment
preflight is in [docs/deploy.md](docs/deploy.md).

Tagged `v*` releases publish one independent archive per Skill through the
repository's release workflow.

## Try the controlled demo

Set `OUTCOMES_GATEWAY_URL` before using a client. A deployed gateway must use
its operator-provided HTTPS origin; clients reject remote plaintext HTTP, URL
credentials, queries/fragments, and redirects.

```powershell
$env:OUTCOMES_GATEWAY_URL = "https://<operator-provided-gateway-origin>"
```

For an operational local **DEMO / NO MONEY** flow, run the loopback-only demo
in one terminal. It uses temporary storage outside this checkout and removes it
on exit.

```powershell
python scripts/run_demo_gateway.py --port 8000
```

In another terminal, use only protected UTF-8 stdin for private buyer input;
never put buyer input in argv, shell interpolation/history, logs, or public
output.

```powershell
$env:OUTCOMES_GATEWAY_URL = "http://127.0.0.1:8000"
Get-Content -Raw -Encoding utf8 .\buyer-input.txt | python skills/outcome-offer/scripts/client.py quote --input-stdin --idempotency-key "demo-001"
python skills/outcome-offer/scripts/client.py fulfill --order-id "<ORDER_ID>"
```

The local demo proves free-test access, private order authorization, and result
delivery without transferring money. It is not a live checkout or evidence of
merchant activation.

```text
python -m pytest tests/test_api.py tests/test_demo_payment.py -q
```

The three linked examples above are controlled free-test fixtures. They show
the result shapes only and have no payment value.

## What the artifacts protect

- The catalog owns product names and the public result contracts.
- Idempotency binds an order to the normalized input, product, currency, and
  locale, preventing a reused key from silently changing the purchase.
- Proof Pack preserves supplied numbers and quotations and identifies derived
  calculations.
- Outcome Offer keeps absent terms visible instead of inventing them.
- Reply to Close advances one next step without inventing a commercial
  concession.
- Output stays behind a private result-access token during the public test.

## What this does not promise

The guarantee is the specified artifact, not an external business result.

- It does not guarantee revenue, leads, conversion, bookings, meetings,
  purchases, or closed sales.
- It does not promise a perfect, brand-ready, factually complete asset without
  human review.
- It does not invent missing evidence, terms, discounts, features,
  testimonials, guarantees, or causal claims.
- It does not promise a business outcome, payment integration, or merchant
  activation.
- The public test is not a real payment, a live checkout, or proof of wallet
  activation.

## Security and privacy boundary

```text
portable Skill -> gateway -> server-owned catalog -> payment adapter
                                             |-> verified result engine
```

The Skills collect the minimum usable input and call the gateway. The gateway
owns order state and result access. Optional future payment adapters are not
enabled in this public test; the result engine receives only the
integrity-checked input for that order.

Never print, log, or serialize private keys, authentication-provider details,
SM4 keys, raw payment credentials, payment proofs, or buyer inputs in public
responses. The repository's `.env.example` contains names and visibly invalid
examples only. Real values belong in a deployment secret manager. See
[SECURITY.md](SECURITY.md) and [docs/activate-live-payments.md](docs/activate-live-payments.md).
